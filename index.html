If saving to the cloud keeps failing on MTN

This is a DNS-level block on supabase.co, not something this page can route around safely. The two real fixes:

  1. Install a DNS app such as 1.1.1.1 (Cloudflare) and turn it on, or
  2. Switch to Airtel/Glo data, or
  3. Deploy your own Google Apps Script proxy (so requests go through script.google.com, which MTN doesn't block) — see the bottom of this page.

Whatever happens, nothing is lost: every save is written to this browser's local storage first, before the app even attempts the cloud request, and duplicates are prevented on save (not just cleaned up after the fact).

Optional: Google Apps Script proxy setup

  1. Go to script.google.com → New Project → Name it SupabaseProxy
  2. Delete the default code and paste this: 
    function doGet(e){ return proxy(e); }
function doPost(e){ return proxy(e); }
function proxy(e){
  var supaUrl = "https://rltzyqqieonretsocass.supabase.co/rest/v1/students";
  var anon = "PASTE_YOUR_ANON_KEY_HERE";
  var opts = {
    method: e.parameter.method || (e.postData ? "POST" : "GET"),
    headers: { apikey: anon, Authorization: "Bearer "+anon, "Content-Type":"application/json", Prefer: "return=representation" },
    muteHttpExceptions: true
  };
  if(e.postData){ opts.payload = e.postData.contents; }
  var res = UrlFetchApp.fetch(supaUrl + (e.parameter.query||""), opts);
  return ContentService.createTextOutput(res.getContentText()).setMimeType(ContentService.MimeType.JSON);
}
  3. Deploy → New Deployment → Web app → Execute as: Me → Who has access: Anyone → Deploy → copy the web app URL
  4. Paste that URL into GOOGLE_PROXY_URL near the top of the script below

Note: only put your anon key in the Apps Script code above (server-side, not visible to visitors) — do not route it through any third-party proxy site.
